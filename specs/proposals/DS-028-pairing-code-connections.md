# DS-028：配对码直接连接，取消人工身份绑定

状态：用户已明确授权产品行为；实现前进行双端代码评审。

## 目标与范围

填写对端地址、端口、相同配对码和本机输入映射后即可开启；首次连接或对端重装不要求确认身份，不要求删除或重建配置。地址/端口用于定向通信，配对码的消息认证是连接凭据。现有随机 endpoint 只保留为报文关联和内部路由缓存，不再作为需要用户信任或确认的身份。

## 协议与兼容

- 保持 version=2、schemaVersion=5、报文字段、NFC/PBKDF2/HMAC、nonce/time-window 和硬件状态机时序不变。此次改变的是发现和路由缓存策略。
- 主动状态探测统一发送 null target，不依赖旧缓存。收到 status_probe 后按配置地址/端口、配对码和唯一匹配选择配置；允许旧版发送的目标缓存过期，但必须完成消息结构、HMAC、时间和重放验证才回复。非探测消息仍定向当前接收实例，保留事件关联和重复硬件动作抑制。
- 本机收到来自已配置地址/端口且配对码正确的有效状态探测或匹配当前检测事件的响应后，可自动更新对端路由缓存，不弹出确认。不得自动开启被用户关闭的配置，不得因探测触发USB/DDC/唤醒/切屏。
- 缓存变化时取消引用旧路由的待处理协同事件，不把旧事件迁移到新实例；配置写入沿用原子保存，失败保留原数据并执行既有安全失败策略。
- 同一地址/端口和凭据匹配多个配置时不得猜测硬件映射；提示配置重复。旧 endpoint 不得优先于地址与配对码，也不得阻止新缓存被学习。
- 本机字段完整的未连接配置可以开启并启动纯状态探测/监听，在线之后自动连接。去掉“待确认身份”、首次/变更身份确认框及以身份为条件的开启校验。
- 新旧版 wire 格式兼容：新版可回复旧版定向探测；旧版可能仍要求人工确认或拒绝对端重装后的实例，因此完整直接连接体验需要双端升级。本次不发送v1、不弱化配对码认证。

## 数据与回退

旧 v5 配置中的 endpoint 保留为可替换缓存，无需丢弃配置或重置本机实例。没有缓存时允许用户保存开启意愿。字段结构不变，不迁移显示器、USB或输入值。回退旧版本前关闭未建立路由的配置；旧版不能保证新行为，旧文件必须保留。

## 双端验收样例

使用模拟地址 alpha.invalid/beta.invalid、合成配对码和随机逻辑ID，不访问真实网络或硬件。

1. 双端从未连接：本机字段完整即可开启，相同配对码的状态交换建立路由，无确认框、无硬件动作。
2. 一端保留旧缓存、另一端重装：有效状态探测更新缓存，两端都恢复；原USB/显示器映射和启用意愿不变。
3. 错误配对码、错误来源地址/端口、过期或nonce冲突：不更新缓存、不回复或执行动作。
4. 有效旧版定向状态探测携带过期target：认证后仅回复当前实例信息；错误目标的硬件消息仍拒绝。
5. 重复状态探测：允许重发状态响应，不重复保存，不重复硬件动作。
6. 用户关闭的配置可响应纯状态检测，但不会被开启或执行协同动作；多个匹配配置不猜测映射。
7. 配置保存失败、取消、USB学习、对端缓存变化后的迟到结果：保留原数据与既有安全门，旧事件不能触发硬件。

## 实施与验证

先评审本提案并同步PROTOCOL，再分别实现Mac和Windows及模拟回归；两端CI均通过后提供双端测试包。Windows x64 Release/原生测试/安装检查，macOS XCTest/Debug/Release/codesign均须通过。实机只验证状态连接，不执行切屏或USB交接。
